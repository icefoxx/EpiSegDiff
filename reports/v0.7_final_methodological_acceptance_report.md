# v0.7 — Final methodological acceptance

## Objective

Build a modular multi-scale differential segmentation stack
that can recover both ~100–1000 bp and multi-kb–>50 kb
events without redefining EpiSegDiff as wide-only, and
without claiming FDR or competitor ranking that the data do
not support.

## Methods

Four layers: observation (existing continuous BigWig path) →
score → segmentation → inference. Primary synthetic cells:
widths `{200, 500, 2000, 10000, 50000}` × `nrep=50` (not 10).
Real assays: GSE280947 JUN, GSE110378 H3K27me3, GSE110378
ATAC (chr1+chr19, 500 bp).

Detection in the factorial used a **frozen MAD threshold** on
segment means. `infer_regions` (limma / descriptive) was used
for inference-architecture nulls. These are not interchangeable.

## Parameters

Synthetic: bin 200 bp, Δ=1.5, noise 0.2, penalty 8.
Production PELT: 200 bp, filter 0.6 (JUN) or quantile 0.75
(H3K27me3), penalty 24, `min_bins=3`.

Standardized score:

```text
Δ / sqrt(s²_pooled + MAD(Δ)²)
```

## Results — required questions

1. **Best score for narrow events?** `standardized` on PELT
   (F1 0.47 / 0.64 at 200 / 500). On `raw_effect`, fused
   lasso F1 0.62 at 200 bp.
2. **Best score for broad events?** `raw_effect` (F1=1 at
   2–50 kb, one call, 0 bp error).
3. **Best calibrated score?** MAD-threshold `raw_effect`
   PELT/fused/WBS: P(any false)=0 on four synthetic nulls.
   `hotelling` / `log_effect` are anti-conservative as
   detectors (tens of extra calls).
4. **Best narrow boundary engine?** Fused lasso, **when it
   fires** (error 0 at 200 bp). Detection rate is 0.62, not 1.
5. **Best broad coherence?** PELT (F1=1, n_call=1, error 0).
6. **Lowest merge rate?** Fused (gap 10: 0.12 vs PELT 0.90).
   WBS merge 0 because it does not call.
7. **Lowest split rate?** PELT/HMM ≈ 0. WBS 0.14 at 50 kb.
8. **Does fused lasso materially improve the baseline?**
   **Yes at 200 bp** (0.62 vs 0). **No as a universal
   engine** (0.06 at 500; 0.64 vs PELT 1 at 50 kb; chr19
   H3K27me3 sign-incoherent).
9. **Does WBS improve narrow sharp events?** **No** in this
   implementation (F1=0 at 200–2000 bp).
10. **Does HMM/HSMM help broad/duration events?** Broad: nearly
    equal to PELT. Duration/nested: **no** (nested still
    merged). Not worth the extra complexity for production.
11. **Does FPOP add practical value?** Not re-established.
    Status: implemented, synthetic-available, not production
    (v0.6 cost issue on real z).
12. **Best single scale at each true width?** 200 bp bins
    throughout this grid. Coarse-to-fine (×5) is worse at
    200 bp and kills 2 kb PELT.
13. **How close is multi-scale to the oracle?** Union =
    oracle at ≥2 kb and = fused at 200 bp. Gap at 500 bp
    remains (union 0.10 vs oracle 0.65 from
    `standardized+PELT min3`).
14. **Does coarse-to-fine improve boundaries?** **No** as
    default. Helps only the 500 bp fused cell.
15. **Does candidate-union improve detection?** It does not
    beat the better single engine. It does not harm broad
    PELT.
16. **Can nested narrow-on-broad be recovered as two
    events?** **No.** `n_merged=1` for PELT, WBS, fused, and
    union.
17. **Boundary error vs effect/noise?** Exploratory n=10:
    fused 500 bp F1 goes 0.9 → 0.1 → 0 as noise 0.1 → 0.2 →
    0.4 at Δ=1.5. PELT 10 kb F1 stays 1 at Δ≥1.5 except
    Δ=0.5 (0).
18. **Gradual boundaries?** PELT F1 0.89 / ~1 kb error vs
    sharp F1 1 / 0. Fused and WBS worse.
19. **Empirical P(any false) by inference?** same-data 0.06;
    pooled 0.08; split 0; cross-fit 0 (WBS).
20. **Does pooled-boundary improve calibration?** **No**
    (0.08 vs 0.06).
21. **Sample-split power loss?** WBS recall 0.12 → 0.02.
22. **Does cross-fitting improve the tradeoff?** Zero false
    calls on the null; power not separately measured beyond
    the union rule. Not shown to beat PELT MAD-threshold.
23. **Is same-data still anti-conservative?** Mildly, under
    `infer_regions` (0.06). Much less than v0.6 unfiltered
    PELT (0.36 / 200 kb). Not a FDR proof.
24. **Pareto-optimal production architecture?** A **pair of
    modes**: raw+PELT min3 (broad default) plus an optional
    narrow overlay (`standardized+PELT min1` or fused).
    Union is safe for isolated events. Automatic roughness
    routing is **not** Pareto-safe.
25. **Is automatic scale selection reliable on held-out
    sims?** **No.** All 2 kb events routed `narrow`; test
    F1 0.52 vs PELT 1.00. 500 bp test F1 0.
26. **Does final EpiSegDiff improve 200–500 bp?** **Yes,
    optionally:** fused 0.62 at 200; standardized+PELT 0.47
    / 0.64. Default PELT min3 remains F1=0 there.
27. **Does it retain 5–100 kb?** **Yes** if the default
    stays PELT. Not if fused or `standardized` is global.
28. **Are real-data boundaries stable?** Penalty 16 vs 24
    Jaccard **1.00** on chr19. Leave-one-JNKi-out Jaccard
    **0**, but that run is descriptive 1+2, not a
    like-for-like replicate test.
29. **JUN direction?** **Yes.** Genome 2/688 LOSS-dominant;
    chr19 fused/WBS/PELT all LOSS-only.
30. **Broad histone coherent?** PELT **yes** (4411/2165
    GAIN). Fused on chr19 **no** (4/12).
31. **Intermediate/open chromatin?** ATAC chr1+chr19
    **runs** (48/1 PELT; 59/2 fused). Not genome-wide, no
    biological lock.
32. **csaw?** NOT_AVAILABLE (no BAM). Not faked.
33. **THOR?** NOT_AVAILABLE. Not faked.
34. **Retained for production?** Continuous BigWig path;
    `raw_effect` + PELT + `min_bins=3`; filter 0.6 / q75;
    modular score/segment/infer APIs; optional
    `standardized` and fused overlay; optional union;
    `refine_segment_edges`; split/cross-fit as diagnostics.
35. **Rejected as defaults?** Global fused, this WBS,
    binseg, `hotelling`, `signed_pval`, `log_effect`,
    coarse-to-fine, roughness auto-router, BH-as-FDR,
    NB-FPOP, “we are first/best vs csaw/THOR”.
36. **Supported claims?** Modular engines are comparable;
    narrow recovery is possible without deleting the broad
    engine; JUN LOSS and H3K27me3 GAIN hold for PELT;
    unfiltered same-data is not a calibrated FDR.
37. **Failure regimes?** 500 bp raw+PELT and raw+fused;
    nested scale separation; WBS narrow; fused on broad
    histone; auto-routing; genome-wide ATAC; BAM
    competitors.
38. **Decision?** **CONDITIONAL PASS**.
39. **Ready for manuscript-focused benchmarking?** **Not
    yet** for a single-engine superiority paper. Ready for
    a methods paper that reports the regime map and keeps
    PELT as the broad default.

## Uncertainty

INFERENCE: v0.7’s value is a **regime map** and a modular
API, not a new universal winner.

SPECULATION: a better WBS penalty or a two-layer HSMM could
still fix nested events; that was not demonstrated.

UNRESOLVED: genome-wide ATAC; BAM-csaw; validated
boundary-confidence; limma FDR grid for every new engine.

## Failures

- Nested merge (Gate F)
- WBS narrow F1=0
- Auto-router unsafe on held-out 2 kb / 500 bp
- Coarse-to-fine harmful at 2 kb
- Fused unsuitable as broad histone engine
- csaw/THOR absent
- Factorial detection ≠ FDR inference

## Interpretation

A CONDITIONAL PASS is the honest outcome: narrow recovery is
no longer structurally impossible, broad PELT still works,
and the method is not a single deployable multi-scale
brain. Do not redefine EpiSegDiff as wide-only. Do not
replace PELT with fused to “win” 200 bp.

## Decision

**CONDITIONAL PASS.**

Core statistical engine is **not** ready for
manuscript-focused *superiority* benchmarking. It is ready
for a methods+calibration writeup that states the tradeoffs.
