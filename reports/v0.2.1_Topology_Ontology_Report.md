# v0.2.1 — Topology ontology (Task B)

**Objective.** Replace overlapping geometry labels with a partition of
\((\Delta_L, \Delta_R, R_W)\). Remove `BIDIRECTIONAL_SHIFT` as a
primary class.

**Hypothesis.** If left/right ends are each classified as out / in /
stable versus \(\delta\), the nine cells plus width predicates are
mutually exclusive. Opposite-end motion is expansion or contraction
(or COMPLEX), never a third “bidirectional shift.”

**Methods.** `classify_geometry_pair()` implements the partition.
Hierarchy: SPLIT/MERGE → INTERNAL (stable outer bounds only) →
one-to-one geometry → COMPLEX. Level I GAIN/LOSS remains separate.

**Simulation design.** 200 examples per primary class (2200 total),
including every 5th example at a just-above-\(\delta\) borderline.
Generator: `simulate_geometry_examples()` /
`simulate_match_class_examples()`.
Config: `config/validation/topology_validation.yaml`.

**Parameters.** \(\delta = 100\) bp, \(\rho = 1.25\), similar-width
ratio 1.25. Seed 20262.

**Results.**

FACT: Confusion (rows = truth, columns = prediction) after the
corrected generator:

- EXPANSION, CONTRACTION, LEFT_SHIFT, RIGHT_SHIFT, SPLIT, MERGE,
  INTERNAL_GAIN, INTERNAL_LOSS, GAIN, LOSS: **200 / 200** each.
- COMPLEX: 148 / 200 self; 52 / 200 called EXPANSION.

FACT: Macro-F1 = **0.976**. Accuracy = **0.976**. COMPLEX rate among
predictions = 6.7%. No row is labeled `BIDIRECTIONAL_SHIFT`.

FACT: The 52 COMPLEX→EXPANSION cases are both-ends-out slivers whose
\(R_W\) still meets \(\rho\). Under the written definition they **are**
expansions. This is a generator-label issue, not a rule overlap.

INFERENCE: EXPANSION and CONTRACTION cannot be emitted as
`BIDIRECTIONAL_SHIFT` because that class no longer exists. Borderline
width failures go to COMPLEX.

**Uncertainty.** Labels are deterministic given coordinates; the only
randomness is example placement.

**Failures.** None of the named geometry classes collide. COMPLEX as a
*truth* label remains a residual set and should not be used as a
positive training target.

**Interpretation.** Gate B mathematical non-overlap holds for the
implemented predicates.

**Limitations.** Examples are interval geometry, not end-to-end NB
simulations (that is Task E).

**Decision: PASS (Gate B)**

**Next action.** Keep COMPLEX as the residual. Do not restore
`BIDIRECTIONAL_SHIFT`.
