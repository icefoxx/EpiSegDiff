# v0.4.2 — Scalability report

## Objective

Report before/after execution of unfiltered whole-genome
segmentation and the engineering properties required by the
taskbook (chromosome independence, restartability, workers).

## Methods

v0.4.1: single `segment_track` over a 13.6M-row track; killed after
>30 min at 100% CPU; `filter=none` recorded `NOT_RUN`.

v0.4.2: `segment_genome` processes one chromosome, checkpoints,
releases the chromosome workspace, then the next. PELT candidate
storage is a pre-sized array (same recurrence). Official engine is
`pelt`.

## Parameters

200 bp, `filter=none`, penalty 24, `min_bins = 3`, workers=1.

## Results

### Does the full genome complete?

FACT: **yes**. 21/21 chromosomes `PASS`. 42,730 tested segments.
See `results/v0.4.2/filter_none/run_manifest.yaml`.

### Runtime

| | v0.4.1 | v0.4.2 |
| --- | --- | --- |
| `filter=none` | NOT_RUN (>30 min then killed) | **2,245 s** completed |
| chr1–19, X PELT | n/a | 5.7–14.9 s each |
| chrY PELT | n/a | **1,983 s** (3 segments) |
| absolute 0.6 (new dispatcher) | 56 s (v0.4.1) | **59 s** (2 GAIN / 688 LOSS) |

Empirical PELT time vs n on chr1 prefixes (unfiltered z):
5k / 20k / 50k / 100k / 200k / 300k → 0.57 / 5.1 / 5.9 / 7.0 / 9.9 /
12.3 s, with max \|R\| saturating near 15,202 on that chrom.
chrY does **not** follow that curve (almost no pruning).

No formal big-O claim is made.

### Peak memory

FACT: chromosome_runtime RSS starts at **7,406 MB** (limma +
genome-wide matrices still live) and falls to **54 MB** after chrY
as R releases. Manifest `peak_rss_mb` = 4,921 MB (sampled around
return). v0.4.1 had no per-chrom RSS log.

### Restartability

FACT: each chromosome writes
`results/v0.4.2/filter_none/checkpoints/chr*.rds` with cache id,
genome, bin size, summary, transform, pseudocount, filter,
segmentation, penalty, min_bins, software.

FACT: a second `segment_genome` on chr19 with the same identity
resumed in 0.026 s. Changing `penalty` to 99 raises
`Incompatible checkpoint`.

### Chromosome independence

FACT: PELT state is created per chromosome. No emitted interval
has mixed `chrom`. Genuine invalid/non-finite/coordinate gaps are
CVR boundaries (`contiguous_valid_regions`). No arbitrary
computational chunks were used.

### Configurable workers

FACT: `execution` is `workers`, `checkpoint`, `resume`. Official
none run used workers=1. `workers=2` equals `workers=1` on a
two-chrom synthetic (testthat).

## Uncertainty

INFERENCE: v0.4.1’s apparent hang was mostly chrY-class PELT plus
a monolithic process with no checkpoint, not a single 13.6M
concatenated series.

## Failures

Experimental FPOP is faster on large chroms but does not match PELT
cost on real z-scores; it is not in the production path.

## Interpretation

Unfiltered execution is production-supported as a **restartable,
chromosome-wise PELT** job. chrY remains expensive and is the
obvious target for a later *equivalent* optimizer, not a parameter
change.

## Limitations

No HPC batch system was used. Peak RSS includes the genome-wide
limma fit, which is still global.

## Decision

Gates B and C: **PASS**.

## Next action

Stop after acceptance. Do not start v0.5 from this report.
