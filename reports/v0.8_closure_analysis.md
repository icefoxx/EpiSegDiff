# v0.8 — Closure analyses R1–R5

## Objective

Separate observation-resolution and parameter effects from
formulation-level failures before any v0.8 architecture freeze.

## Methods

`nrep=50` on every primary cell. Detection rule is the v0.7
frozen MAD threshold (`0.15 + 0.35·MAD`), not limma FDR.

Configs:

```text
raw_pelt_min3     production baseline
raw_pelt_min1     same score, floor removed
std_pelt_min1     best v0.7 narrow PELT score
raw_fused_min1    best v0.7 narrow engine
```

Seeds start at 90000. Runtime 1307 s.

## Parameters

R1 resolutions `{50,100,200}` bp × widths
`{100,200,300,500,750,1000,2000}` bp, Δ=1.5, noise=0.2.

R2 200 bp bins, widths 2 kb and 10 kb, gaps
`{0,1,2,3,5,10,20}` bins, Δ=1.5.

R3 broad = 20 kb / 100 bins; local = 400 bp / 2 bins.
`B ∈ {0.6,1.2,1.8}`, `L ∈ {±0.6,±1.2,±1.8}`.

R4 gradual 20% ramps at 5 / 10 / 25 kb.

## Results

### R1 — resolution × narrow width

FACT: finer bins **do not** rescue `raw_effect` + PELT at
100–300 bp. At 50 bp resolution those cells remain F1 = 0
(min1 and min3).

FACT: PELT becomes perfect once the event covers about **10
bins** at this penalty/Δ/noise:

| resolution | first width with raw+PELT F1≈1 |
| --- | --- |
| 50 bp | 500 bp (10 bins) |
| 100 bp | 1000 bp (10 bins) |
| 200 bp | 2000 bp (10 bins) |

So the v0.6 `min_bins=3` floor was **not** the only scale
limit. Penalty 8 + raw effect imposes an ~10-bin detection
length.

FACT: `standardized` + PELT detects 100–300 bp at all three
resolutions (`P(detect) ≥ 0.94`) but fragments (`n_call`
2–6 at 50 bp). Unconditional F1 0.44–0.72. Conditional
boundary error grows with width (0 at 100 bp / 200 bp res;
1900 bp at 2 kb / 50 bp res).

FACT: fused, when it fires, has **conditional boundary error
0**. `P(detect)` stays 0.12–0.68 and is **not** monotonically
improved by 50 bp bins (100 bp event: 0.12 at 50 bp vs 0.54
at 200 bp).

INFERENCE: part of the 500 bp v0.6 failure was
observation-resolution (500 bp at 50 bp is easy for PELT).
100–300 bp raw+PELT failure is **not** fixed by resolution
alone.

### R2 — same-direction gap curve

FACT (PELT `n_merged`):

| gap (bins) | 2 kb events | 10 kb events |
| --- | ---: | ---: |
| 0–5 | 1.00 | 1.00 |
| 10 | 0.84 | **0.00** |
| 20 | **0.00** | 0.00 |

Separation phase boundary ≈ **10 bins (2 kb)** for 10 kb
blocks and **20 bins (4 kb)** for 2 kb blocks.

FACT: fused merge falls at gap ≥ 1 (0.06–0.20) but F1 stays
0.55–0.78 because detection is incomplete.

INFERENCE: PELT’s broad coherence is bought by merging
same-direction neighbors across multi-kb neutral gaps.
Fused separates earlier and misses more.

### R3 — nested B × L

FACT: `raw_pelt_min3` same-direction `n_merged = 1.00` and
`P(n_call ≥ 2) = 0` for **every** `(B, L)` pair.

FACT: opposite-direction PELT still merges
(`n_merged` 0.58–1.00); F1 stays high because one interval
covers both truths.

FACT: `std_pelt_min1` can emit extra calls when `|L|` is
large (`P(n_call ≥ 2)` → 1 at L=1.8) but `n_merged` remains
≈ 1: a spanning segment still exists. That is fragmentation
on top of merge, not two-scale identity.

FACT: fused same-direction `n_merged` 0.96–1.00.

INFERENCE: nested failure is **not** a single `(B, L)`
corner. It is systematic for the flat one-layer partition.

### R4 — transition zones

FACT (means):

| width | config | F1 | core recall | trans recall | over-ext | mid err | point bound err |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 5 kb | PELT | 0.89 | 1.00 | 0.49 | 0.00 | 46 | 1012 |
| 10 kb | PELT | 0.89 | 1.00 | 0.52 | 0.00 | 112 | 1936 |
| 25 kb | PELT | 0.90 | 1.00 | 0.53 | 0.00 | 198 | 4740 |
| 5–25 kb | fused | 0.34–0.38 | ~1 | 0.82–1.00 | **0.77** | 0.4–8.9 kb | 18–82 kb |

FACT: PELT recovers the **core** and about **half** of each
ramp, with no background over-extension. Point-change
boundary error is 1–5 kb because truth includes ramps.

FACT: fused covers transitions by **over-extending** into
background (~77% of predicted bp).

INFERENCE: a single-point boundary is the wrong estimand for
ramp truth. PELT is a decent core finder, not a transition
localizer.

### R5 — P(detect) vs E[error | detect]

FACT: fused 200 bp-class cells have `P(detect)` 0.12–0.68 and
conditional error **0**. Unconditional F1 equals
`P(detect)` because misses dominate.

FACT: `std_pelt` has `P(detect) ≈ 1` and nonzero conditional
error that scales with width (fragment edges).

FACT: raw+PELT is binary: `P(detect)=0` below ~10 bins,
then `P(detect)=1` and conditional error 0 on sharp blocks.

INFERENCE: quoting fused “0 bp error” without
`P(detect)` is misleading. Both numbers are required.

## Uncertainty

UNRESOLVED: WBS retuning, fused λ paths, and PELT penalty
paths were **not** grid-searched. R1 used the frozen v0.7
penalty 8. A different penalty could move the ~10-bin PELT
threshold. It is unlikely to produce nested two-object
recovery (R3 is a representation failure, not a 10-bin
floor).

SPECULATION: 50 bp + a lower PELT penalty might recover some
300–500 bp raw-effect cells. That would still leave nested
and gradual-transition structure.

## Failures

No effect×noise×width 50-rep cube (only Δ=1.5 / 0.2). No
WBS retune. No limma FDR in these cells (MAD rule only).

## Interpretation

| Question | Answer |
| --- | --- |
| Resolution-only explanation of narrow failure? | **No** for 100–300 bp raw+PELT. **Partial** for 500 bp. |
| One engine now Pareto-acceptable narrow+broad? | **No.** |
| Nested still systematically merged? | **Yes.** |
| Same-dir separation vs fragmentation tradeoff? | **Yes.** |
| Point-change vs gradual structurally poor? | **Yes** (half-ramp missed or 77% over-ext). |
