# v0.4 Phase 1 — width / min_bins investigation

**Objective.** Explain v0.3 `200 bp × min 3 bins` vs median LOSS width **400 bp**.

**Trace**

1. `min_width` is a **bin count**, applied inside PELT/OP.
2. PELT skipped the minimum only when `t < n`, so the **final** segment of a CVR could be 1–2 bins.
3. A CVR with `n < min_width` was emitted as a single segment (the “safe” one-bin path).
4. After signal masking, many JUN islands were 2 bins = **400 bp**.
5. `width = end - start` on 0-based `[start,end)` equals `n_bins * bin_size` for complete interior bins. 400 = 2×200. There was no post-trim and no BED ±1 bug on the toy `[300,700)` test.
6. Chromosome-end tiles can be shorter than `bin_size`; that is a separate, smaller effect.

**FACT:** The 400 bp median was **2-bin emitted segments**, not a coordinate conversion error.

**Fix:** `.enforce_min_bins()` merges/drops segments with `n_bins < min_width`. A series shorter than `min_width` emits nothing. Regression: `test-v04-continuous.R` / `test-segmentation.R`.

**Acceptance:** emitted `n_bins >= min_bins`; genomic width ≥ `min_bins * bin_size` on uniform tiles.
