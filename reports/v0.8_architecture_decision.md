# v0.8 — Architecture decision gate

## Objective

Choose Path A (targeted engine refinement) or Path B
(hierarchical / multiresolution redesign) using only the
locked v0.7 review plus R1–R5.

## Methods

Section 20 of the review spec. No new architecture was
implemented. Two-mode overlay remains a **control**, not the
accepted method.

## Section 20 checklist (after fair resolution check)

| Criterion | Evidence | Holds? |
| --- | --- | --- |
| 1. No single engine acceptable on narrow **and** broad | raw+PELT F1=0 at 100–300 bp even at 50 bp; std+PELT fragments; fused `P(detect)` 0.12–0.68 | **Yes** |
| 2. Nested events remain systematically merged | PELT same-dir `n_merged=1` and `P(n_call≥2)=0` for all B×L; fused `n_merged≈1` | **Yes** |
| 3. Better same-dir separation fragments or misses | PELT separates 2 kb neighbors only at gap ≥20 bins; fused separates at gap 1 with F1 0.55–0.78 | **Yes** |
| 4. One-scale routing unstable | v0.7 held-out: 2 kb all routed narrow, F1 0.52 vs PELT 1.00 | **Yes** (prior) |
| 5. Gradual remains structurally poor under point-change | PELT trans recall ~0.5; fused over-ext ~0.77 | **Yes** |

## Decision

**Path B is authorized as the scientific direction.**

**Path A is rejected as the primary plan.** Resolution and
`min_width` explain the 500 bp / 10-bin PELT corner and
nothing else that blocked v0.7.

**Full v0.8 engine implementation is not started in this
turn.** Path B needs its own specification covering:

```text
D(x) = B(x) + L(x) + ε(x)
```

or an equivalent hierarchical / multiresolution objective,
plus the ten falsification tests in Section 10 of the review
spec.

## What v0.8 must not do

- Freeze `raw+PELT` + optional fused/`standardized` as the
  final architecture.
- Claim region-level FDR from MAD-threshold nulls.
- Claim superiority to csaw/THOR.
- Hide nested merge behind union F1.
- Implement wavelets / residualization / HSMM trees before
  a written Path B spec with identifiability and null tests.

## What remains allowed as controls

- Production PELT 200 bp / min3 / filter 0.6 or q75.
- Optional narrow overlay tables (not silent auto-route).
- The modular score/segment/infer APIs from v0.7.

## Inferential target (must be declared in any Path B spec)

Discovery, boundary estimation, effect estimation, testing,
and multiplicity are separate. The target must be one of:

```text
per-region type-I error
FDR over selected regions
false differential bp
family-wise P(any false region)
```

They are not interchangeable.

## Manuscript

Still **method-development only**. R1–R5 strengthen the
regime map and the nested/formulation inference. They do
not create a publishable universal engine.

## Uncertainty

INFERENCE: shared nested failure across engines after
resolution correction is the strongest argument that the
**objective**, not the bin size, is wrong.

UNRESOLVED: a heavily retuned WBS or fused-λ path was not
run. That cannot overturn R3 (PELT/fused/std all merge
nested same-direction structure).

## Failures

No Path B prototype. That is intentional.

## Interpretation

v0.7 asked which engine to use at each scale. After R1–R5
the question is the one the review stated:

> What statistical representation of genomic differential
> signal can simultaneously preserve broad domains, local
> narrow changes, nested structure, accurate boundaries,
> and valid inference?

## Decision (one line)

**v0.7 CONDITIONAL PASS stands. Path B authorized. Path A
rejected. No v0.8 production engine in this release.**

## Next action

Stop for formal review of R1–R5 and this decision. A later
Path B specification may implement `D = B + L + ε` against
the Section 10 falsifiers.
